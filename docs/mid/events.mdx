---
title: "EVENTS track"
description: "Practice sections, the coda, the song's end and other song-wide text events in a .mid file."
---

The `EVENTS` track holds the text events that apply to the whole song: practice sections, the coda and the song's end. Each is a text event, `FF 01`:

```text
EVENTS
  0       Track name  EVENTS
  0       Text        section Intro
  7680    Text        section Verse 1
  61440   Text        coda
  76800   Text        end
  76800   End of track
```

It's the `.mid` form of a `.chart` file's [[Events]](/chart/events) section. One thing differs: a `.mid` file holds its lyrics in its vocal tracks.

- A file has at most one `EVENTS` track, after the tempo track. See [Tracks](/mid/structure#tracks).
- A scanner matches every event below in the letter case shown.
- A scanner reads the text by the [bracket rule](/chart/syntax#text) of a `.chart` file: as written first, then inside its first pair of square brackets, or after a `[` at the start that no `]` closes. So `[section Intro]` means the same as `section Intro`. **Recommended:** no brackets.
- Text that reads as a lyric, such as `lyric x`, or as `phrase_start` or `phrase_end`, isn't an event for the rule here, since `EVENTS` holds no lyrics, so `lyric x [coda]` is the coda.
- **Required:** the event is the whole text, with no spaces around it or just inside its brackets.
- Only a text event, `FF 01`, holds these events: a lyric, marker or cue point event holds none of them.

## Practice sections

A practice section marks where a part of the song starts, such as the intro or a verse. It runs until the next practice section:

```text
<tick>  Text  section <name>
```

- **Required:** a space or `_` between `section` and the name. **Recommended:** a space.
- **Required:** one practice section at most at a tick.
- **Recommended:** at least one practice section in a chart.

**Edge case: the names Clone Hero shows.** Clone Hero has a table of Rock Band section names, and shows a name from it when it finds one there, such as `Verse 1` for `verse_1`. It shows any other name with each `_` replaced by a space. It does the same in a `.chart` file.

**Edge case: a chart with no practice sections.** When a song with no practice sections is played, Clone Hero makes ten, named `0% - 10%` to `90% - 100%`. They start at tenths of the chart's length, which ends a beat after the last note. It does the same in a `.chart` file. YARG makes the same ten, at tenths of the chart's last tick. scan-chart reports `noSections`.

## Lyrics

A `.mid` file holds its lyrics, and the phrases that group them, in its vocal tracks. See [Vocals and harmonies](/mid/vocals).

## The coda

```text
<tick>  Text  coda
```

`coda` marks where the song's big ending starts. A drum fill at or after it is a Big Rock Ending. See [Drum fills](/mid/phrases#drum-fills). **Required:** one `coda` at most.

## The end of the song

```text
<tick>  Text  end
```

`end` ends the song before its audio does, as in a `.chart` file. See [The end of the song](/chart/events#the-end-of-the-song).

- **Required:** `end` at least one beat after the end of the last note of every track, sustain included.
- **Required:** one `end` at most.

## Deprecated

- **`prc_<name>`,** an older word for `section`: `prc_verse_1` is a practice section named `verse_1`. Write `section <name>` instead.

## Ignored

- **Any other text.** YARG acts on a few more events, such as `crowd_clap`, and reads `midcoda` and `midcoda_end` as the start and end of a coda. Other scanners ignore them. An exporter should keep them when rewriting a file.
- **Notes and other events that aren't text,** such as Rock Band's practice notes 24, 25 and 26. scan-chart keeps them, and writes them back.

## Invalid forms

<Accordion title="Spaces around the text, or just inside the brackets">
Clone Hero, YARG and scan-chart read ` section Intro ` and ` [section Intro] `, with spaces around the text, as a practice section, and none of them reads `[ section Intro]`. scan-chart keeps such text as it is.
</Accordion>

<Accordion title="A practice section name with spaces at its ends">
Clone Hero and scan-chart keep the spaces: `[section  Intro ]` is a section named ` Intro ` there. YARG removes them.
</Accordion>

<Accordion title="No separator after section">
Clone Hero skips the character after `section`, so `[sectionIntro]` is a section named `ntro`. YARG reads a section named `Intro`. scan-chart doesn't read it as a section.
</Accordion>

<Accordion title="A practice section with no name">
Clone Hero and scan-chart read `[section ]` and `[prc_]` as a section named "", and YARG ignores them.

Clone Hero also reads `[section]` and `[prc]` as a section named "". YARG and scan-chart ignore both. scan-chart keeps the text.
</Accordion>

<Accordion title="Two practice sections at one tick">
Clone Hero, YARG and scan-chart use the later one.
</Accordion>

<Accordion title="Lyrics or phrase events in EVENTS">
Clone Hero ignores them. YARG reads `lyric` events, `phrase_start` and `phrase_end` as lyrics, mixed with the lyrics of `PART VOCALS`. scan-chart reports `invalidLyric`, `invalidPhraseStart` and `invalidPhraseEnd`, and keeps them. Its `.chart` export leaves them out, since `[Events]` would play them, and its conversion report lists them.
</Accordion>

<Accordion title='Text outside the brackets, such as [prc_intro] "Intro"'>
A scanner reads the event inside the brackets, by the [bracket rule](/chart/syntax#text), so this is the section `intro`. Some charts write their sections so, such as Chaotrope's Rock Band Network songs. Clone Hero reads it as the section `intro] "Intro`, and YARG as the section `intro`. scan-chart reads it as a scanner does. Saving with scan-chart keeps the text as written, and its export writes `[section intro]`.
</Accordion>

<Accordion title="A [ at the start that no ] closes, such as [section Chorus 2">
A scanner reads the text after that `[`, by the [bracket rule](/chart/syntax#text), so this is the section `Chorus 2`. A `[` later in the text doesn't count: `x [section Chorus 2` holds no event. Some charts have such a typo. Clone Hero reads the section without its last character, as `Chorus `. YARG and scan-chart read it as a scanner does. Saving with scan-chart keeps the text as written, and its export writes `[section Chorus 2]`.
</Accordion>

<Accordion title="A song-wide event in a lyric, marker or cue point event">
A scanner ignores it, as Clone Hero and YARG do. Some charts write `[end]` or their practice sections as lyric events. scan-chart keeps such an event with its type, and its `.mid` export writes it back so. Its `.chart` export leaves it out, and its conversion report lists it.
</Accordion>

<Accordion title="A coda with one bracket or text around it, after a byte order mark, or in another type of text event">
A scanner reads the coda by the bracket rule, and only from a text event, `FF 01`. So `[coda] - Big Rock Ending` is the coda, and so are `[coda`, which starts with a `[` that no `]` closes, and a `[coda]` after a byte order mark, U+FEFF: the mark isn't white space, but the coda is inside the first pair of brackets. `x [coda` and `coda]` aren't the coda, nor is `coda` after a byte order mark, or a coda written as a lyric, marker or cue point event. scan-chart reads them so, except `coda` after a byte order mark: it drops the mark when it decodes the text, so it reads a coda there. Its export writes `coda]` back as it was, and its `.chart` export leaves out a coda in a lyric, marker or cue point event. Clone Hero reads a coda only from `coda` or `[coda]` with nothing around it but white space. YARG reads them as scan-chart does, a coda after a byte order mark included.
</Accordion>

<Accordion title="More than one coda or end">
Clone Hero and scan-chart use the first `coda` and the first `end`, and YARG uses the first `coda`. YARG looks for `end` among the song's last 10 song-wide events, and uses the last one it finds there. scan-chart reports `badEndEvent` for each `end` after the first. Its export writes a coda at the start of each Big Rock Ending instead of where the file had it, so Clone Hero reads the same Big Rock Endings.
</Accordion>

<Accordion title="An end less than a beat after the last note ends">
Clone Hero ignores it, and plays until the later of the end of the audio and the end of the last note. YARG uses it when it comes after the end of every note, phrase and lyric, with no one-beat margin. scan-chart reports `badEndEvent` when it comes before the last note starts.
</Accordion>

<Accordion title="A second EVENTS track">
Every scanner reads the first `EVENTS` track and ignores the others. scan-chart's export leaves them out.
</Accordion>
